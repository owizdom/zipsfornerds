# Spec 0001: ZIPs For Nerds site v1

- **Status:** PROPOSED. Wisdom asked for the build to start on 20 Sep 2026 ("start building it and make the repo private"); he reviews this spec with the first draft PR.
- **Owner:** Claude Fable 5.1 (architect, test-writer and implementer in one session; a separate reviewer agent grades the diff).

## 1. Objective

A static website for the ZIPs For Nerds research series, in the editorial style of research-studio sites such as schemaresearch.xyz (serif body, mono labels, warm paper background), with its own identity.

Done means:

1. `npm run build` produces a fully static site in `out/` with these routes: `/`, `/articles/<slug>/`, `/zips/`, `/about/`, `/rss.xml`.
2. Articles are plain markdown files in `articles/` with frontmatter. Adding an article is adding a file.
3. An article with `status: draft` never appears in a production build: no route, no index entry, no RSS item.
4. Every published article page shows its ZIP number and status, who reviewed it, its corrections log, its AI disclosure and its sources.
5. `/zips/` lists every ZIP the series plans to cover with its current status, target upgrade, spec link, and a link to the explainer once one is published.
6. The built site makes zero third-party requests: fonts are self-hosted, there is no analytics script, no embeds.
7. A published article cannot ship with an unresolved placeholder or a style-rule violation. The build's test gate fails instead.

## 2. Non-goals

- No CMS, comments, newsletter signup, search, dark-mode toggle or analytics in v1.
- No deployment, domain or DNS work in this spec. Deploying needs Wisdom's explicit OK and the domain.
- No publishing of article #1. It stays `status: draft` until the fact-check is applied and Wisdom has read it.
- No copying of schemaresearch.xyz's assets, copy or brand. Same genre, own design.

## 3. Stack

Next.js (App Router, `output: 'export'`), TypeScript, plain CSS, markdown rendered at build time with unified/remark/rehype. Tests run on the built `out/` directory with Node's built-in test runner.

```
app/            routes: home, articles/[slug], zips, about, rss.xml
articles/       markdown articles (content)
zips/           zips.json, the coverage index (content)
lib/            content loading, markdown rendering, lint rules
tests/          acceptance tests against out/
docs/           spec, TASKS, JOURNAL
```

## 4. Seam contract

```
lib/content.ts   getArticles({ includeDrafts }) -> Article[]      # sorted newest first
                 getArticle(slug) -> Article | null
                 Article = { slug, title, subtitle, zip, zipStatus, zipCategory, date, status: 'draft'|'published',
                             reviewedBy, corrections: string[], disclosure, readingMinutes, html, outline }
lib/zips.ts      getZips() -> ZipEntry[]                           # { zip, title, status, upgrade, specUrl, articleSlug? }
lib/lint.ts      lintPublished(markdown) -> string[]               # violations; empty means clean
```

Production builds call `getArticles({ includeDrafts: false })`. `next dev` shows drafts, marked DRAFT.

## 5. Acceptance tests

**T** = automated (run by `npm test`, which builds first). **L** = live/manual.

| # | Test | Type | Passes when |
|---|---|---|---|
| AT1 | Static routes exist | T | `out/index.html`, `out/zips/index.html`, `out/about/index.html`, `out/rss.xml` exist after build |
| AT2 | Drafts never ship | T | With a fixture draft and a fixture published article, only the published slug has a route, a home entry and an RSS item |
| AT3 | Article page carries its accountability block | T | A published article's HTML contains its ZIP number, ZIP status, "Reviewed by", "Corrections", "Disclosure" and a Sources heading |
| AT4 | Zero third-party requests | T | No `src`/`href` on `script`, `link`, `img`, `iframe` or CSS `url()` in `out/` points at another origin. Outbound `<a>` links are allowed |
| AT5 | Published content passes lint | T | `lintPublished` returns no violations for every published article: no em or en dashes, no "Stanford", no unresolved `[BRACKET]` placeholders |
| AT6 | Lint catches violations | T | `lintPublished` flags a fixture containing an em dash, a `[LINK]` placeholder and "Stanford" |
| AT7 | ZIP index is consistent | T | Every `zips.json` entry has zip, title, status, upgrade and an https spec URL; every `articleSlug` resolves to a published article |
| AT8 | RSS is well-formed | T | `out/rss.xml` parses, has a channel title, and its item count equals the published article count |
| AT10 | Figures | T | An image with a title renders as a captioned `<figure>`, and every local image referenced in `out/` exists |
| AT9 | Tripwire | T | The run fails if zero tests ran or any test was skipped |
| AL1 | Looks right on phone and desktop | L | Wisdom views home, an article and the ZIP index at 390px and 1280px |

## 7. Pre-mortem: "this shipped and failed; why?"

| # | Failure | Mitigation in this spec |
|---|---|---|
| 1 | The unverified ZIP 318 draft goes live by accident and a ZIP author finds an error | AT2: drafts cannot be built into production. Article #1 stays `draft` |
| 2 | An article ships with "[REFRESH ON PUBLICATION DAY]" or a disclosure placeholder still in it | AT5 fails the gate on any unresolved bracket placeholder in a published article |
| 3 | A privacy-focused audience finds a Google Fonts or analytics request on the site | AT4 scans the built output for third-party origins |
| 4 | The site looks like a clone of schemaresearch.xyz | Own palette, own type pairing, own layout details; no assets or copy reused |
| 5 | An explainer goes stale when its ZIP changes status | `/zips/` holds status in one JSON file; each article shows a corrections log with dates |
| 6 | Tests pass because they ran against nothing | AT9 tripwire; tests assert on fixtures that must exist |

## 8. Rollout, rollback, removal

- **Rollout:** draft PR from `agent/site-v1` into `main`. Wisdom merges. Deployment is a separate step that needs his OK and the domain.
- **Rollback:** revert the merge commit. Nothing is deployed by this spec.
- **Removal:** the two fixture articles under `tests/fixtures/` stay as test data and are never copied into `articles/`.
